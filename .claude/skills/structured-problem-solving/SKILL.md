# Structured Problem Solving

Work through these stages in order. Keep each one short; depth goes where the problem is hardest.

## 1. Define the problem
- Restate the problem in one sentence: current state -> desired state, and the gap between them.
- List what is known, what is assumed, and what is unknown. Mark assumptions explicitly.
- Name constraints (time, money, skills, rules) and what "solved" looks like (a measurable success test).
- If a missing fact would change the answer, ask for it. Otherwise state the assumption and move on.

## 2. Find the real cause
- Ask "why?" until you hit something actionable (5 Whys), or sort causes into buckets (people, process, tools, environment, information).
- Separate symptoms from causes. Solve causes.
- Check whether the stated problem is the real problem (the XY problem).

## 3. Generate options
- Produce at least three genuinely different approaches, including the simplest one and doing nothing.
- For each: how it works, cost/effort, risk, time to result.

## 4. Decide
- Compare options against the success test and constraints (a small table works well).
- Recommend one. Say why, and what would make you pick a different one.

## 5. Plan
- Numbered steps, each starting with a verb, each small enough to start today.
- For each step: what "done" looks like, rough time, and any dependency.
- Add a checkpoint: how to tell early whether the plan is working, and the fallback if it is not.

## 6. Pressure-test
- What is the most likely way this fails? Add a step that prevents it.
- Is anything in the plan something the person cannot actually do? Replace it.

## Output rules
- Lead with the recommendation, then the steps. Put analysis after, briefly.
- No filler, no motivational padding. Concrete nouns and numbers over adjectives.
